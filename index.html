BACnet Networking: The Fundamentals

Unlike typical web applications that communicate using point-to-point HTTP/TCP client-server architectures, Building Automation and Control networks (BACnet) heavily rely on device discovery (Who-Is/I-Am) through network-wide broadcast mechanisms.

Because BACnet utilizes broadcasts for establishing bindings, a solid grasp of Layer 2 and Layer 3 subnet boundaries is critical. Misconfigurations in subnetting can easily cause devices to be discoverable but unable to communicate, or completely invisible across network segments.

1. Layer 2 vs Layer 3: BACnet/Ethernet vs BACnet/IP

BACnet/Ethernet (ISO 8802-3)

BACnet/Ethernet is a Layer 2 (Data Link) protocol. Devices communicate directly using raw Ethernet frames and MAC addresses. It does not use IP addresses.

Critical Limit: Because routers only forward Layer 3 (Network) traffic, BACnet/Ethernet frames cannot cross routers. They are strictly confined to the same physical switch segment (broadcast domain).

BACnet/IP (Annex J)

BACnet/IP wraps BACnet frames inside standard UDP/IP (Layer 3 & 4) packets (usually on port 47808 / 0xBAC0).

Benefit: Because it uses IP, BACnet/IP can traverse routers, allowing BACnet traffic to scale across large campus buildings and corporate WAN networks.

2. IP Subnets & Broadcast Address Intersection

What is a Subnet Broadcast?

In BACnet/IP networks, a device broadcasts a "Who-Is" service request to locate another device by its instance number (e.g. Device ID 10001). This request is sent to the Subnet Broadcast Address.

Every IP network has a unique network ID and a broadcast address. The broadcast address is calculated by setting all the host bits of the subnet to binary 1. Any device on that local segment listening to that broadcast address will process the packet.

The Broadcast Intersection Trap
Consider Device A on 192.168.0.5/23 and Device B on 192.168.1.6/24.
  • Device A Broadcast IP: 192.168.1.255
  • Device B Broadcast IP: 192.168.1.255
They share the exact same broadcast address and hear each other's broadcasts if plugged into the same switch. However, Device B's network is 192.168.1.0/24, so it does not believe Device A (192.168.0.5) is local, and attempts to send replies through a router gateway, breaking direct unicast!

Resulting Symptoms:
  • Who-Is (Broadcast) requests reach both devices correctly.
  • Device A replies/requests unicast directly to Device B (using Layer 2 MAC translation).
  • Device B rejects A as local, forwarding packets to its Gateway router. If routing fails or lacks a return route, Device B cannot reply to A.

3. Traversing Subnets: BBMD Infrastructure

The Router Problem

By design, IP routers drop UDP broadcast packets to prevent "broadcast storms" from flooding the wider corporate network. However, because BACnet/IP discovery relies on broadcasts, BACnet devices on Subnet A cannot find devices on Subnet B under normal conditions.

The Solution: BBMD (BACnet Broadcast Management Device)

A BBMD is a device (or software service on a BACnet controller) that coordinates broadcasts across subnets. Exactly one BBMD must be configured on each subnet segment. When a broadcast is sent on Subnet 1:

  • The local BBMD 1 captures the broadcast.
  • It wraps the broadcast inside a directed unicast UDP packet (using the BVLL - BACnet Virtual Link Layer header).
  • It sends this unicast packet through the router directly to BBMD 2 on Subnet 2.
  • BBMD 2 extracts the original broadcast and rebroadcasts it on Subnet 2.

FDR: Foreign Device Registration

If a remote subnet only has a single BACnet device (like a technician's laptop), setting up a dedicated BBMD is overkill. Instead, the laptop can register as a Foreign Device (FDR). The laptop periodically registers its IP address with a primary BBMD, which then relays broadcasts directly to the laptop via unicast UDP.
